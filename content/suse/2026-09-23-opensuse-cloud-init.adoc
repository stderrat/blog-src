We were running https://www.freebsd.org/[FreeBSD] on an
https://pcengines.ch/apu2.htm[PC Engines APU2] as a firewall/DNS/DHCP
server for a very long time. Because of reasons we wanted to migrate
services running on the APU2 to a VM running on a
https://www.synology.com/en-global/products/DS1525+[Synology NAS]. As
operating system we picked https://get.opensuse.org/leap/16.0/[openSUSE Leap 16.0].
The Synology NAS is based on Linux and uses https://linux-kvm.org/page/Main_Page[KVM (Kernel-based Virtual Machine)] as a virtualization solution.

This blog post describes how we installed openSUSE LEAP 16.0 on the VM
and how we used cloud-init for the base configuration.

<!--more-->

To summerize we had the following goals:

- Setup a Synology VM. This will be done manually for now. One option
  for automation might be using an
  https://github.com/RowanXB/synology-vmm[Agent Skill]. But this is
  another story.
- Use https://docs.cloud-init.io/en/latest/[cloud-init] to deploy day 1 configuration settings to the virtual machine
- Migrate DNS and DHCP configuration from old system to the new VM.

== Getting an openSUSE Leap image with cloud-init support

openSUSE provides an https://get.opensuse.org/leap/16.0/#download[KVM
and XEN image] (you have to click on _Alternative Downloads_). The
problem with this image is that does **NOT** come with
cloud-init. Upon first-boot it will ask some basic questions about the
root password and timezones, so not what we want.

But thanks to openSUSE's https://openbuildservice.org/[Open Build
Service (OBS)] it relativly easy to create a custom KVM image with
cloud-init support.

The OBS web interface needs some getting used to but we will describe
the steps required in a bit. There is also a
https://openbuildservice.org/help/manuals/obs-user-guide/cha-obs-osc[command
line client for OBS called osc], but as OBS is new for us we sticked
to the web ui.

== Branching the KVM openSUSE image and adding cloud-init support via OBS

The first step for using OBS is to create a user. As this is pretty
much straight forward we will not cover all the details here. Just
head over to https://build.opensuse.org/ and hit _Sign up_ in the upper left corner. This
takes you to the
https://idp-portal.suse.com/univention/self-service/#page=createaccount[create
account] page.

After signing up and login in for the first time you are redirected to
the Welcome page.

Next we need to branch the KVM minial image. There are to options:

- Either head over to https://docs.harvesterhci.io/v1.8/advanced/customsuseimages/ and follow the instructions. Just for reference this uses
https://build.opensuse.org/image_templates for creating the branch. You have to select **"openSUSE Leap 16.0 Minimal"**.

- Use OBS directly to branch the KVM template and modify the configuration.

For unkown reasons we selected option two. So after logging in to OBS you have to execute the follow steps:

1. After logging in select _New Image_, this takes you to the https://build.opensuse.org/image_templates page:
+
image::obs_new_image.png[alt=Create new image]

2. Select the _openSUSE Leap 16.0 Minimal_ image:
+
image::obs_leap_image.png[alt=Select the LEAP image]

3. Give the new appliance a name and click _Create appliance_:

image::obs_appliance_name.png[alt=Select the LEAP image]

This takes you to the web editor for the file _Minimal.kiwi_:

image::obs_edit_kiwi.png[alt=Edit kiwi file]

For reasons unknown to us the _Minimal.kiwi_ file had some errors.

https://en.opensuse.org/Portal:KIWI[Kiwi] is new for use but the XML
file was pretty much self-explainable.

We replaced the default configuration with the following (important
changes we did are marked with number and explain below the XML file):
